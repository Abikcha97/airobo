## Новая услуга: «Снятие наличных с карты»
### Платёжная система ELPAY — Web + Android POS-терминал

**Версия:** 1.0  
**Дата:** Июнь 2026  
**Адресовано:** Frontend-разработчикам (Web) и Backend-инженерам  

---

## 1. КОНТЕКСТ ПРОЕКТА

В платёжной системе ELPAY внедряется новая услуга — **«Снятие наличных с карты» (Card Cash Out)**.

### Текущие платформы:
- **Веб-версия** для компьютеров (интерфейс оператора-кассира)
- Приложение для **Android POS-терминала**

### Агентская сеть (финансовый контекст):
- 50+ платёжных агентов (в форме ООО / ИП)
- Каждый агент имеет **депозитный счёт** в системе ELPAY
- Агент пополняет депозит путём **банковского перевода** со своего расчётного счёта на счёт ELPAY ООО

### Движение средств в существующих услугах:
```
Клиент → передаёт наличные → Агенту
Агент  → списывает с депозита → производит оплату (депозит уменьшается)
```

### Движение средств в новой услуге (ОБРАТНОЕ):
```
Клиент → данные карты → Транзакция → списание с карты
Списанные средства → ЗАЧИСЛЯЮТСЯ на депозит Агента
Агент  → выдаёт клиенту → наличные
```

## 2. ОПИСАНИЕ УСЛУГИ

### Название: Снятие наличных с карты  
### English: Card Cash Out / Cash Withdrawal from Card

### Основной процесс (пошагово):

| # | Шаг | Кто выполняет | Канал |
|---|-----|---------------|-------|
| 1 | Выбор услуги | Оператор-кассир | Web / POS |
| 2 | Ввод номера карты клиента | Кассир или Клиент | Web / POS |
| 3 | Ввод срока действия карты | Кассир или Клиент | Web / POS |
| 4 | Отправка SMS OTP на телефон, привязанный к карте | Система (автоматически) | SMS Gateway |
| 5 | Ввод SMS OTP-кода | Кассир (от клиента) | Web / POS |
| 6 | Ввод суммы для снятия наличных | Кассир или Клиент | Web / POS |
| 7 | Автоматический расчёт и отображение комиссии | Система (автоматически) | Web / POS |
| 8 | Нажатие кнопки «Оплатить» | Кассир | Web / POS |
| 9 | Выполнение транзакции | Система (processing) | Backend |
| 10 | Списание с карты, зачисление на депозит агента | Система (автоматически) | Backend |
| 11 | Печать чека | Система (автоматически) | Web / POS Printer |
| 12 | Кассир выдаёт наличные клиенту | Кассир | Физически |

## 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 3.1 Frontend (Web — интерфейс оператора/кассира)

#### Новая страница / модальное окно: «Снятие наличных с карты»

**Поля формы:**

| Поле | Тип | Валидация | Примечание |
|------|-----|-----------|------------|
| Номер карты | `input[type=text]` | 16 цифр, проверка по алгоритму Луна | Маска: `0000 0000 0000 0000` |
| Срок действия | `input[type=text]` | Формат MM/YY, прошедшая дата — ошибка | Маска: `MM/YY` |
| SMS OTP | `input[type=number]` | 4–6 цифр | С таймером (60 сек) |
| Сумма | `input[type=number]` | Мин/Макс ограничения, целое число | Согласно лимиту агента |
| Комиссия (авто) | `readonly` | — | Рассчитывается на Backend |
| Итого к списанию | `readonly` | — | Сумма + Комиссия |

**Кнопки:**
- `Отправить OTP` — отправка SMS (debounce: повторная отправка не ранее 60 сек)
- `Выполнить транзакцию` — активна только после прохождения всех валидаций
- `Отмена` — очистка формы

**Индикаторы состояния:**
- `Проверка карты...` — spinner
- `OTP отправлен` — сообщение об успехе + таймер
- `Транзакция выполнена ✓` — зелёный цвет, данные чека
- `Ошибка: [текст ошибки]` — красный цвет, конкретная причина

---

### 3.2 Frontend (Android POS-терминал)

Аналогичный процесс, адаптированный под **UI/UX POS-терминала**:

- Крупный шрифт, удобные для нажатия кнопки (min 48dp)
- Ввод номера карты вручную или автоматически через **считыватель карт (card reader)**
- Поле OTP — цифровая клавиатура
- Чек — печать через термопринтер
- Работа только в онлайн-режиме (нет офлайн-операций)

### 3.3 Backend / API

#### Новые API-эндпоинты:

```
POST /api/v1/cashout/initiate
  Body:     { card_number, expiry_date, agent_id }
  Response: { session_id, masked_phone, otp_sent: true }

POST /api/v1/cashout/verify-otp
  Body:     { session_id, otp_code }
  Response: { verified: true, card_holder_name, available_limit }

POST /api/v1/cashout/execute
  Body:     { session_id, amount, agent_id, operator_id }
  Response: { transaction_id, status, receipt_data, agent_balance_after }

GET /api/v1/cashout/receipt/{transaction_id}
  Response: { данные чека в формате PDF/JSON }
```

#### Бизнес-логика (Backend):

1. **Проверка карты** — интеграция с процессинговым центром (существующая)
2. **Генерация и отправка OTP** — через SMS Gateway
3. **Проверка лимитов:**
   - Достаточно ли средств на карте?
   - Достаточно ли наличных у агента для выдачи клиенту?
   - Соблюдение дневных / месячных лимитов (compliance)
4. **Выполнение транзакции:**
   - Списание с карты: `сумма + 1% комиссии` (через OSON)
   - OSON удерживает 1% комиссию (0.6% — чистый доход OSON)
   - На депозит агента зачисляется только **основная сумма**
   - Вознаграждение OSON → ELPAY (0.4%) и ELPAY → Агент (0.2%) выплачиваются **при ежемесячном закрытии**
5. **Генерация чека**
6. **Запись в журнал аудита**

## 4. ФИНАНСОВАЯ СХЕМА (FINANCE FLOW)

### 4.1 Структура участников (3 уровня)

```
OSON  (собирает 1% комиссию, 0.6% оставляет себе, 0.4% возвращает ELPAY)
  └── ELPAY ООО  (агент OSON: получает 0.4%, отдаёт 0.2% своим агентам)
        └── Агенты ELPAY  (получают 0.2% — ежемесячно)
```

> ELPAY сам является **агентом OSON**. Поэтому OSON собирает 1% комиссии и возвращает ELPAY его вознаграждение (0.4%). ELPAY, в свою очередь, выплачивает вознаграждение своим агентам (0.2%).

---

### 4.2 Движение средств в момент транзакции (Real-time)

```
┌───────────────┐
│  КАРТА КЛИЕНТА│  сумма + 1% комиссии
│               │  (пример: 50 000 + 500 = 50 500 сум)
└───────┬───────┘
        │
        ▼
┌──────────────────────────────────────────────────┐
│               OSON PROCESSING                    │
│  Вся комиссия 1% (500 сум) поступает к OSON      │
│  OSON удерживает 0.6% (300 сум) — чистый доход   │
│  OSON возвращает ELPAY 0.4% (200 сум) — ежемес.  │
└──────────────────┬───────────────────────────────┘
                   │
          основная сумма (50 000 сум)
                   │
                   ▼
┌──────────────────────────────────────────────────┐
│           РАСЧЁТНЫЙ СЧЁТ ELPAY ООО               │
│  Основная сумма транзитом проходит к агенту      │
└──────────────────┬───────────────────────────────┘
                   │
         50 000 сум (основная сумма)
                   │
                   ▼
┌──────────────────────────────────────────────────┐
│             ДЕПОЗИТ АГЕНТА ELPAY                 │
│  (+50 000 сум зачисляется)                       │
└──────────────────┬───────────────────────────────┘
                   │ выдаёт наличные
                   ▼
            ┌──────────────┐
            │    КЛИЕНТ    │
            │ 50 000 сум   │
            │ наличными    │
            └──────────────┘
```

---

### 4.3 Распределение комиссии (1% = 500 сум, пример: 50 000 сум)

| Сторона | % | Сумма | Когда | Примечание |
|---------|---|-------|-------|------------|
| **Клиент** платит | **1.0%** | 500 сум | В момент транзакции | Списывается с карты |
| **OSON** удерживает | **0.6%** | 300 сум | В момент транзакции | Чистый доход OSON |
| **OSON → ELPAY** вознаграждение | **0.4%** | 200 сум | При ежемесячном закрытии | ELPAY как агент OSON |
| **ELPAY → Агент** вознаграждение | **0.2%** | 100 сум | При ежемесячном закрытии | Зачисляется на депозит агента |
| **ELPAY** чистый доход | **0.2%** | 100 сум | После ежемесячного закрытия | 0.4% − 0.2% = 0.2% |

---

### 4.4 Движение средств при ежемесячном закрытии

```
OSON  ──(0.4% вознаграждение)──►  РАСЧЁТНЫЙ СЧЁТ ELPAY
                                           │
                                 ┌─────────┴──────────────┐
                                 │                        │
                       0.2% вознаграждение          0.2% чистый
                       агентам ELPAY                доход ELPAY
                                 │                        │
                                 ▼                        ▼
                         ДЕПОЗИТ АГЕНТА            ELPAY ООО
                         (зачисляется)             (чистая прибыль)
```

## 6. ТРЕБОВАНИЯ БЕЗОПАСНОСТИ

| Требование | Описание |
|------------|----------|
| Срок действия OTP | Не более 60 секунд |
| Попытки ввода OTP | Максимум 3 попытки, после — сессия блокируется |
| Срок действия сессии | Максимум 5 минут от initiate до execute |
| Данные карты | Хранятся на Backend по стандарту **PCI DSS**; на фронтенде — только маскированные |
| TLS/HTTPS | Все API-запросы шифруются |
| Журнал аудита | Каждое действие (initiate, OTP send, verify, execute, fail) записывается в лог |
| Аутентификация оператора | Кассир должен быть авторизован в системе (PIN/пароль) |
| Защита от двойного списания | Одна сессия может быть выполнена только один раз |

## 10. КРИТЕРИИ ПРИЁМКИ (Definition of Done)

Услуга считается завершённой при выполнении следующих условий:

- [ ] Клиент вводит данные карты и подтверждает транзакцию через OTP
- [ ] Транзакция успешно выполняется, средства списываются с карты
- [ ] Корректная сумма зачисляется на депозит агента
- [ ] Кассир и клиент получают чек
- [ ] Все ошибочные ситуации отображаются корректно
- [ ] Услуга работает как на Web, так и на POS-терминале
- [ ] Журнал аудита ведётся полностью
- [ ] Генерация ежемесячного акта сверки работает корректно
- [ ] Нагрузочный тест: не менее 50 одновременных транзакций без сбоев
- [ ] Пройдена проверка безопасности

## 12. АГЕНТСКОЕ ВОЗНАГРАЖДЕНИЕ (МУКОФОТ ПУЛИ)

### 12.1 Общие положения — 3-уровневая агентская система

```
OSON  (собирает 1%, 0.6% — себе, 0.4% — возвращает ELPAY)
  └── ELPAY ООО  (получает 0.4%, 0.2% — своим агентам, 0.2% — себе)
        └── Агент ELPAY  (получает 0.2% — ежемесячно на депозит)
```

Вознаграждения выплачиваются **не в момент транзакции**, а **в конце каждого месяца** при закрытии счёта-фактуры.

---

### 12.2 Порядок ежемесячной выплаты вознаграждений

**Шаг 1:** OSON закрывает месяц → перечисляет ELPAY вознаграждение 0.4%  
**Шаг 2:** ELPAY закрывает месяц → зачисляет каждому агенту 0.2% на депозит  
**Шаг 3:** У ELPAY остаётся 0.2% чистого дохода

---

### 12.3 Пример расчёта вознаграждения (транзакция 50 000 сум)

| Сторона | % | Сумма | Момент | Примечание |
|---------|---|-------|--------|------------|
| **Клиент** платит | 1.0% | **500 сум** | В момент транзакции | Списывается с карты |
| **OSON** удерживает | 0.6% | **300 сум** | В момент транзакции | Чистый доход OSON |
| **OSON → ELPAY** вознаграждение | 0.4% | **200 сум** | При ежемес. закрытии | ELPAY как агент OSON |
| **ELPAY → Агент** вознаграждение | 0.2% | **100 сум** | При ежемес. закрытии | Зачисляется на депозит |
| **ELPAY** чистый доход | 0.2% | **100 сум** | После закрытия | 0.4% − 0.2% = 0.2% |

### 12.5 Структура ежемесячных счетов-фактур

Каждый месяц система генерирует **два типа** счетов-фактур:

#### А) OSON → ELPAY (счёт-фактура на вознаграждение)
```
Ежемесячное вознаграждение ELPAY = Σ (сумма каждой транзакции × 0.4%)
```

| Столбец | Данные |
|---------|--------|
| Период | Прошедший месяц |
| Кол-во транзакций | — |
| Общая сумма обналичивания | — |
| Итого комиссий (1%) | — |
| Вознаграждение ELPAY (0.4%) | — |
| Чистый доход OSON (0.6%) | — |

#### Б) ELPAY → Каждый агент (счёт-фактура на вознаграждение)
```
Ежемесячное вознаграждение агента = Σ (сумма транзакций агента × 0.2%)
```

| Столбец | Данные |
|---------|--------|
| Период | Прошедший месяц |
| Наименование агента | ООО / ИП |
| Кол-во транзакций | — |
| Общая сумма обналичивания | — |
| Вознаграждение агента (0.2%) | — |
| Дата выплаты | Дата закрытия месяца |
| Статус | Выплачено / Ожидается |

### 12.7 Ключевые правила

> ⚠️ **В момент транзакции:** На депозит агента зачисляется только основная сумма. Вознаграждение НЕ выплачивается.  
> ✅ **При ежемесячном закрытии:** OSON → ELPAY (0.4%), затем ELPAY → Агент (0.2%) — последовательно.  
> 📊 Доля вознаграждения по каждой транзакции рассчитывается в реальном времени и хранится в таблице `cashout_rewards`.  
> 🔗 ELPAY является **агентом OSON** — поэтому работают два параллельных уровня системы вознаграждений.
